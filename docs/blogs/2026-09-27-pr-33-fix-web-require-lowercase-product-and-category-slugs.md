## fix(Web): Require lowercase product and category slugs

- **Release tag:** `v0.0.13`
- **Source PR:** [#33](https://github.com/mpaulosky/atelier-store/pull/33)

### PR description

Fixes #16.

## Problem

`ProductCatalog.FindBySlugAsync` and `GetRelatedAsync` lowercase the slug they look up, but nothing stopped a row being stored with uppercase letters. A product saved as `Mixed-Case` could never be found, even by its own slug. The unique index on `slug` is also case-sensitive, so `Foo` and `foo` could both exist.

## Changes

- Adds two check constraints, both `slug = lower(slug)`, with a migration (`SlugLowercaseConstraints`):
  - `ck_products_slug_lowercase`
  - `ck_categories_slug_lowercase`
- Replaces the integration test that pinned the buggy behavior (`FindBySlugAsync_ProductStoredWithAMixedCaseSlug_CannotFindItByItsOwnSlug`) with two tests in `DatabaseConstraintTests` that check saving an uppercase product or category slug throws `DbUpdateException`.
- Notes the lowercase rule in the root `CLAUDE.md`.

The lookup code doesn't change. The constraint also makes the unique index effectively case-insensitive, since every stored slug is lowercase.

## Migration note

The seeded slugs are all lowercase, so the migration applies cleanly to a fresh or seeded database. A database that already has an uppercase slug will fail to migrate until that row is fixed. No code in the app writes products or categories yet.

## Checks

- The solution builds with `-warnaserror`.
- All 27 integration tests pass against Postgres 17, with every migration applied. The two new tests failed before the constraints were added.
