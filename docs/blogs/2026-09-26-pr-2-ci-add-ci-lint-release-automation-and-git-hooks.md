# ci: Add CI, lint, release automation, and git hooks

- **Release tag:** `v0.0.1`
- **Source PR:** [#2](https://github.com/mpaulosky/atelier-store/pull/2)

## PR description

### Summary

Brings in the shared GitHub automation (workflows, git hooks, release and blog scripts, Copilot instructions and a code-review skill) and adapts it to Atelier Store.

**CI and checks**
- `ci.yml` "Build Solution" (the required check on `main`) now sets up pnpm and Node for the Tailwind build, and replaces `build.yml`. Test, coverage and report jobs skip cleanly while there are no test projects. New jobs run the Python script tests and the pre-push hook tests.
- CodeQL uses buildless C# analysis, because autobuild would need pnpm.
- Lint Markdown and Lint YAML, with the new `.markdownlint-cli2.jsonc` and `.yamllint.yml`.
- Dependabot for Actions, NuGet, the .NET SDK and the web project's pnpm packages, plus auto-merge for its PRs.

**Git hooks** (`.github/hooks`, `core.hooksPath`)
- `pre-commit`: Markdown lint on staged files.
- `pre-push`: branch naming (`feature/{issue}-{slug}`, `hotfix/{issue}-{slug}`, `chore/{slug}`), then the new `scripts/gate.sh`: lint changed Markdown and YAML, Release build, then every test project.

**Release automation**
- `release.yml`: each merged PR gets a version tag, a GitHub Release and a blog-post PR under `docs/blogs`.
- `backfill-blog-posts`, `sync-readme`, `code-metrics`: use `RELEASE_PR_PAT` when it's set; code-metrics skips its PR without it.
- `pr-automerge`: squash-merges PRs once checks pass, Copilot has reviewed the head commit, and every review thread is resolved. It also runs every 15 minutes.

**Docs**
- The Blazor instructions and code-review skill are rewritten for this app. The template described another project.
- Long lines in both `CLAUDE.md` files are wrapped (no wording changes), a bare URL in the README is fixed, and the README Layout table lists the automation.
- `build-log.txt` is gitignored.

### Needs repository settings

- Secrets: `RELEASE_PR_PAT` for automation PRs; optionally `ANTHROPIC_API_KEY` (AI summaries in blog posts) and `AUTH0_*` (future tests).
- Or allow GitHub Actions to create pull requests (Settings → Actions → General).
