# chore(agents): Add Beast Mode custom agent without gate-bypassing tools

- **Release tag:** `v0.0.9`
- **Source PR:** [#22](https://github.com/mpaulosky/atelier-store/pull/22)

## PR description

### Summary

Adds the GPT-4.1 "Beast Mode" custom agent, `.github/agents/beast.agent.md`, for VS Code Copilot Chat.

Changes from the upstream agent:

- **Removed tools that make changes on GitHub without the local hooks.** These are `github/push_files`, `create_or_update_file` and `delete_file`, `update_pull_request_branch`, and `copilotCodingAgent` / `assign_copilot_to_issue`, which hand work to the hosted coding agent. I also dropped the `github/github-mcp-server/*` wildcard, which would have added all of them back.
- **Removed `merge_pull_request`**, so the agent can't merge its own PRs.
- **Removed `create_repository` and `fork_repository`**, which this repo doesn't need.
- **Treats fetched content as untrusted.** The agent follows only links relevant to the request, and ignores and reports instructions it finds in fetched content.
- **Research uses tools that exist.** It uses the configured `fetch` tool and the Microsoft Docs tools instead of `fetch_webpage` or Google search, and happens only when the task needs it.
- **Explicit git-safety rule.** The agent must not use `--no-verify`, override `core.hooksPath`, or push to `main`.
- **Removed `runNotebooks`, `runTasks`, `extensions` and `run_subagent`.** Notebook cells and task definitions can run `git` outside the terminal approval rules, extensions run arbitrary code, and a subagent could bring back the removed write tools. The Playwright browser tools are kept for checking the UI, but the agent is told to use them only on `localhost`.
- **Markdown structure.** Adds a `# Beast Mode` H1 and orders the headings correctly.

### What enforces this

The agent keeps its terminal tools (`runCommands` and `run_in_terminal`) because it needs them to build and test. The prompt rule is guidance, not a barrier. What actually stops a bypass:

1. **VS Code terminal approval.** VS Code asks before running any terminal command that isn't auto-approved, and checks each sub-command of a chained command separately. The workspace `.vscode/settings.json` (merged in #21, and on this branch) auto-approves only `git add` and `git commit`. Its deny rules make any `--no-verify`, `git commit -n`, or `core.hooksPath` override always need approval, even when chained after an approved command.
2. **The `main-rules` ruleset.** It requires a PR and passing required checks (`Build Solution`, `actionlint`, `zizmor`, `shellcheck`), blocks force-pushes and deletion, and has no bypass actors. Commits that skipped the local hooks still can't reach `main` without CI.

**Scope of these limits.** The local controls (the prompt rules, VS Code approval, and the local hooks) reduce the risk; they don't guarantee anything. Any agent that can edit code and then run it (for example with `runTests`) could reach `git`. The enforced boundary is the server-side ruleset: nothing reaches `main` without a PR and green CI.
