# chore: Standardize on the repo-ci-baseline Template

- **Release tag:** `v0.0.42`

## PR description

Brings atelier-store onto the shared repo-ci-baseline Template from dotfiles (`Support For New Projects/.claude/skills/repo-ci-baseline`). From now on, CI, release, lint and hook files are kept in step by re-Applying the Template, not edited by hand here.

### Commits

1. **`chore: apply repo-ci-baseline Template`**: exactly what `apply.sh` wrote. Drift from atelier-store's real fixes (#84's HTML handling in `release_post.py`, `.env` in `.gitignore`, pnpm lockfile and `pnpm dlx`, the 80% coverage gate, the npm Dependabot entry) went into the Template first, in mpaulosky/dotfiles#15, so none of it is lost.
2. **Adapt:**
   - `.github/ci/prepare.sh` enables pnpm through corepack. It replaces the old `ci.yml`'s pnpm and Node setup steps and runs in the build job and every test job.
   - `src/AtelierStore.Web/.gitignore` ignores the generated `wwwroot/app.css`, because the root `.gitignore` is now Owned by the Template.
   - Removes `sync-readme.yml`, since `release_post.py` already keeps `docs/README.md` up to date.
   - Dependabot keeps its npm entry and gains the Template's Testcontainers group.

### What changes in behavior

- The required check **`Test Report Summary` is renamed `Test Suite`**. The ruleset is updated in the same sitting as the merge.
- The coverage gate reads `.github/ci/coverage-threshold` (80, as before).
- `code-metrics.yml`: a manual run now opens a metrics PR only when the new `publish` input is ticked (it's off by default, because the reports undercount classes with primary constructors), and that PR's title carries `[skip-release]`.
- `global.json`: SDK roll-forward goes from `latestFeature` to `latestMinor` (a later minor SDK is now accepted), and prerelease SDKs are explicitly off. This is the Template's policy for every repo.
- `.editorconfig`: the Template's version drops atelier-store's test-project CA suppressions, the `*.generated.cs` CS0200 suppression and the StyleCop SA1633/SA1636 lines. None of them had any effect here: no `AnalysisMode`, no StyleCop, no generated files, and the build is clean without them. If a later change turns those analyzers on, the suppressions go into the Template first.
- `ci.yml` passes `MongoDB__ConnectionString` from an optional `MONGODB_CONNECTION_STRING` secret, which is IssueTracker's. atelier-store doesn't have that secret, so the variable is empty. Making test secrets per-repo is a Template follow-up.
- The Template's CodeQL workflow replaces the local copy (comment wording only).
