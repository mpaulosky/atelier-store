# ci(hooks): Adopt the shared branch-name standard

- **Release tag:** `v0.0.37`
- **Source PR:** [#92](https://github.com/mpaulosky/atelier-store/pull/92)

## PR description

### Summary

Part 1b of #86, porting mpaulosky/IssueTracker#182: the branch-name standard every repo now shares.

- **`fix/{issue}-{slug}`** is accepted alongside `feature/` and `hotfix/`.
- **A `chore/` slug starts with a letter**, so `chore/7-cleanup` can't pass for an issue-linked name.
- The hook's message lists all four patterns, and `docs/CONTRIBUTING.md` and the code-review skill's branch line match.

| Pattern | Use |
| --- | --- |
| `feature/{issue}-{slug}` | New features |
| `fix/{issue}-{slug}` | Bug fixes |
| `hotfix/{issue}-{slug}` | Urgent fixes |
| `chore/{slug}` | Work without an issue |

`squad/` and `sprint/` stay refused, as before.

### Testing

- New hook cases: each accepted prefix (including slugs with digits) runs the gate, and each retired or malformed name is refused: `squad/`, `sprint/`, a prefix missing its issue number, an uppercase letter in a slug (`feature/9-Upper`, `chore/tidy-Up`), and a `chore/` slug starting with a digit.
- Against the old hook, two of the new cases fail (`fix/2-fix-a-thing` refused, `chore/7-cleanup` accepted). With the change: 48 passed, 0 failed. A hook that allowed uppercase fails the two uppercase cases.
- `shellcheck` is clean, and this branch was pushed through the new hook, whose gate passed.
