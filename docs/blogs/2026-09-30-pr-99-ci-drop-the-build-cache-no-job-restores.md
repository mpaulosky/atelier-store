# ci: Drop the build cache no job restores

- **Release tag:** `v0.0.40`
- **Source PR:** [#99](https://github.com/mpaulosky/atelier-store/pull/99)

## PR description

### Summary

Part 4 of #86, porting mpaulosky/IssueTracker#178.

- **Removes "Cache build artifacts"** from the build job. It cached `bin/` and `obj/`, but no job ever restored that cache: each test matrix job restores and builds its own project. The step also ran *after* the build, so its restore did nothing either. On the last three `main` runs it cost 5 to 8 seconds per build. It held 14 caches, about 1.1 GB of the repo's 7.9 GB of Actions cache (10 GB limit), crowding the NuGet caches the jobs do use.
- **Adds a comment on the test job** recording why the matrix stays without a shared build. IssueTracker measured the options in #144, 3 runs each: sharing the build output with `--no-build` saved nothing, because packing and downloading ~164 MB costs as much as the build; one job running every project used 60% fewer runner-minutes but took about 1.5 minutes longer.

The NuGet package cache stays. The existing `Linux-build-*` caches age out on their own.

### Testing

- `yamllint`, `actionlint` and `zizmor` are clean, and the pre-push gate passed.
- This PR's own CI runs the build and all four test projects without the step.
