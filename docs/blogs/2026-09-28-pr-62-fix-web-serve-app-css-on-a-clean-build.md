## fix(web): Serve app.css on a clean build

- **Release tag:** `v0.0.26`
- **Source PR:** [#62](https://github.com/mpaulosky/atelier-store/pull/62)

### PR description

`wwwroot/app.css` is generated by the `TailwindBuild` target and isn't committed. But `wwwroot/**` is collected when the project first loads, before the file exists. On a clean build, which is every CI run, the file was therefore left out of the static-asset manifest, and `@Assets["app.css"]` couldn't serve it. Only a second build picked it up.

I reproduced this on a fresh checkout of `main`: after the first build, `staticwebassets.build.json` had no `app` entry, and after the second it did. The target now adds the file to `@(Content)` right after generating it, so the first build lists it.

This is the same fix as in mpaulosky/TicketManager#92, mpaulosky/IssueManager#220 and mpaulosky/Articles#270, which also stop committing their generated CSS. The pre-push gate passed.
