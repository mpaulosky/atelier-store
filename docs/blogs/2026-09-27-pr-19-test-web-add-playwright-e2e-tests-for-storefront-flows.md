## test(Web): Add Playwright E2E tests for storefront flows

- **Release tag:** `v0.0.7`
- **Source PR:** [#19](https://github.com/mpaulosky/atelier-store/pull/19)

### PR description

Slice 5 of 6 of the test plan. Closes #7.

## Scope (`tests/AtelierStore.Web.Tests.E2E`)

- **Host**: `AtelierAppFactory : WebApplicationFactory<Program>` runs on a real, in-process Kestrel listener (`UseKestrel(0)` + `StartServer()`, dynamic loopback port) in the `Development` environment, so static web assets and the Blazor Server script are actually served. `ServerAddress` reads `ClientOptions.BaseAddress` (touching the `Server` property throws once `UseKestrel` is requested).
- **Database isolation**: one assembly-wide `postgres:17` Testcontainer (`E2EFixture`), migrated with `Database.MigrateAsync()`. On top of the merchandising seed data, the fixture inserts two E2E-owned products (`e2e-signature-trench`, always in stock; `e2e-heritage-tweed-scarf`, no stock row at all) with high, explicit IDs and old `CreatedAt` values so they never appear in "New in" and tests assert against fixture-owned data, not seed data.
- **Auth**: `TestAuthHandler` is the default authenticate/challenge/sign-in scheme; it authenticates only when the `e2e-auth` cookie is present (set via `IBrowserContext.AddCookiesAsync`). Auth0 is never called. Note `AddAuth0WebAppAuthentication` sets its own `DefaultAuthenticateScheme`, which wins over `DefaultScheme` in the auth middleware unless explicitly overridden too — the factory overrides all four `AuthenticationOptions` scheme properties.
- **Config isolation**: `ConfigureAppConfiguration` injects the Testcontainers connection string and dummy Auth0 settings; the fixture also claims the `Auth0__*`/`ConnectionStrings__Default` environment variables before startup so `DotNetEnv.NoClobber()` (which Program.cs runs on a `.env` from a parent directory) can never leak the developer's real settings into the E2E host.
- **Serial execution**: `E2ECollection` (`DisableParallelization = true`) puts every test class in one collection sharing the fixture's one browser/one database.
- **Artifacts on failure**: `PlaywrightTestBase` starts tracing per test when `PLAYWRIGHT_ARTIFACTS=true`, and on a failed test saves a trace + full-page screenshot under `bin/<config>/<tfm>/TestResults/playwright-artifacts/`.

## Scenarios (all 7, Chromium only, role/name locators)

1. `HomeToProductTests` — 8 "New in" cards; clicking one opens `/products/{slug}` with a matching `h1` and price (captured from the card, so it isn't tied to specific seed data).
2. `AddToBagTests` — the in-stock fixture product's "Add to bag" shows "Added to your bag." after the enhanced, antiforgery-protected form post.
3. `SoldOutProductTests` — the sold-out fixture product has a disabled "Sold out" button and the "may return" notice.
4. `NewsletterTests` — a valid email shows "You're on the list."; see the bug note below for the invalid-email half.
5. `ProductNotFoundTests` — an unknown slug renders the not-found page.
6. `HeaderAuthStateTests` — anonymous shows "Log in", signed-in (via the fake cookie) shows "Log out".
7. `MobileNavTests` — at 390×844 the drawer opens and lists the primary nav links.

## Bugs found and filed (not fixed here — test-only PR)

- #17 — the newsletter's "Enter a valid email address." server message is unreachable through a real browser: `type="email"`'s native HTML5 constraint validation blocks submission before the message could ever be shown, for any input that would trigger it. `NewsletterTests.InvalidEmail_BlocksSubmission_BeforeItReachesTheServer` documents the actual (native-blocked) behavior with a `// BUG: #17` comment.
- #18 — the mobile "Menu" toggle (`<summary aria-label="Menu">`) has no exposed accessible role in Chromium's accessibility tree, so it isn't reachable via `GetByRole` and isn't perceivable as an interactive control by assistive tech. `MobileNavTests` falls back to a CSS attribute locator with a `// BUG: #18` comment.
