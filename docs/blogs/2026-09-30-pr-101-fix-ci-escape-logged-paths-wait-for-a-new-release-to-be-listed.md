# fix(ci): Escape logged paths; wait for a new Release to be listed

- **Release tag:** `v0.0.41`
- **Source PR:** [#101](https://github.com/mpaulosky/atelier-store/pull/101)

## PR description

### Summary

The last follow-up for #86: three fixes IssueTracker found after this repo's ports had merged.

- **Logged paths can't start a workflow command** (mpaulosky/IssueTracker#188). Git allows line breaks in file names, and `detect_changes.py` writes the first code path to the Actions log, so a name like `src/x\n::error::forged` could start a workflow command. The path is logged with `\r` and `\n` escaped. Git's output is also decoded by hand, because `subprocess.run(text=True)` turned a `\r` in a name into `\n`.
- **Wait for a just-published Release to be listed** (mpaulosky/IssueTracker#190). IssueTracker's v0.0.20 got no blog PR: the `docs` job started 8 seconds after the Release was published, the release list didn't include it yet, and the job reported every Release as already having its post. The `docs` job now passes the plan's queue as `--wait-for-prs`, and `backfill_blog_posts.py` lists Releases again until each of those PRs has one. The posts and the tables use that one listing. A Release that never appears is logged as a warning, and the next run writes its post.
- **Every 2 seconds, for up to 30** (mpaulosky/IssueTracker#192): the lag seen was under 8 seconds.

`detect_changes.py`, `backfill_blog_posts.py`, their tests and `release.yml` now match IssueTracker's. This repo's copies were identical to IssueTracker's from before these fixes.

### Testing

- All script tests: 215 passed, including the new cases for a path holding `\n::error::` and `\r::warning::`, a Release listed only on a later attempt, a Release that never appears, and the tables reusing the posts' listing.
- `yamllint`, `actionlint` and `zizmor` are clean, and the pre-push gate passed.
