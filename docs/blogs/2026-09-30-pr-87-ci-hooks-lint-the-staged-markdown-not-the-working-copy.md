# ci(hooks): Lint the staged Markdown, not the working copy

- **Release tag:** `v0.0.35`
- **Source PR:** [#87](https://github.com/mpaulosky/atelier-store/pull/87)

## PR description

### Summary

Part 1 of #86, porting mpaulosky/IssueTracker#170. `.github/hooks/pre-commit` ran markdownlint on the working-tree paths, so with a partly staged Markdown file the working copy could pass while the staged version (the one committed) failed, and only CI caught it.

- The hook writes each staged `.md` file's **staged content**, plus the staged `.markdownlint-cli2.jsonc`, into a temporary tree with the same layout (`git checkout-index --prefix`), and lints that tree. The config's ignores still apply.
- Staged paths are read NUL-separated, so paths with spaces work, and renamed files (`R`) are linted under their new name.
- Only a staged config is used; one that exists only in the working copy isn't in the commit.
- This repo's `pnpm add -g` install hint is kept.
- New `.github/hooks/tests/pre-commit.test.sh`, run by CI's **Hook tests** job, which now names it in its comment.

### Testing

- `pre-commit.test.sh`: 12 cases pass. They cover staged-only versus working-copy-only violations, a real staged rename, a staged config that differs from the working one, an unstaged config, an ignored path, a path with spaces, and a deletion. The stub linter applies the config it finds, so the suite fails if the hook lints under the working-copy config.
- `shellcheck`, `yamllint`, `actionlint` and `zizmor` are clean, and the pre-push gate passed.
