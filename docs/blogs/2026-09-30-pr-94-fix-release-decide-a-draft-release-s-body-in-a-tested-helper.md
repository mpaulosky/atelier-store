## PR description

### Summary

Part 2 follow-up for #86: the draft-Release fixes that mpaulosky/IssueTracker#184 found after #90 had already merged here.

When the release job finds a draft Release for the tag it reserved, it publishes it. The body it publishes with now comes from a tested helper, `.github/scripts/draft_release.py`, instead of inline shell:

- **Notes appended unless already named:** the release notes (with the `Source PR: #n` line the planner and ordering guard look for) are appended unless the draft already names this PR on a line of its own. LF and CRLF endings both count, so a CRLF draft isn't given the notes twice.
- **A draft naming another PR fails the job**, rather than publish one Release with two sources. Markers count anywhere in a line, the pattern `release_post.source_pr_of()` uses, so a list item like `- Source PR: #5` is caught.

`release.yml`, `draft_release.py` and `test_draft_release.py` now match IssueTracker's exactly; the rest of the workflow already did.
