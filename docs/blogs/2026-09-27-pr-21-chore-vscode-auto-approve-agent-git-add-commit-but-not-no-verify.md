# chore(vscode): Auto-approve agent git add/commit but not --no-verify

- **Release tag:** `v0.0.8`
- **Source PR:** [#21](https://github.com/mpaulosky/atelier-store/pull/21)

## PR description

### Summary

Adds a shared `.vscode/settings.json` that lets chat agents run `git add` and `git commit` without a confirmation prompt, while still asking before any command that bypasses the repo's git hooks.

VS Code matches string keys in `chat.tools.terminal.autoApprove` against the start of a command, so `"git add"` and `"git commit"` on their own would also auto-approve hook bypasses, including ones chained after an approved command. These deny rules win over the allow rules and match anywhere in the command line:

| Rule | Denies |
|---|---|
| `/--no-verify\b/` | `--no-verify` on any command (`git commit`, `git push`) |
| `/\bgit\s+commit\b.*\s-[A-Za-z]*n[A-Za-z]*(?=$\|[\s;&\|)])/` | `git commit -n` and combined flags like `-anm`, including before `;`, `&&`, `\|` or `)` |
| `/\bcore\.hooksPath\b/i` | overriding `core.hooksPath` (`git -c core.hooksPath=/dev/null commit`, `git config core.hooksPath`) |

### Validation

- Tested 22 command strings. Ordinary commits (`-m`, `-am`, `-F -`, `--amend --no-edit`), `git add -n` and `git add -A && git commit -m ok` stay approved. Every bypass variant, including chained ones like `git add -A && git commit --no-verify` and `git commit -n;`, needs approval.
- The JSON is valid and follows `.editorconfig` (tabs, LF endings).
- The pre-push gate passed: Release build with `-warnaserror`, and 47/47 tests.

### Note

A commit message that happens to contain ` -n ` will also ask for approval. That errs on the safe side.
