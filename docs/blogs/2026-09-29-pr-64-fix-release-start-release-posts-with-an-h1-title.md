# fix(release): Start release posts with an H1 title

- **Release tag:** `v0.0.28`
- **Source PR:** [#64](https://github.com/mpaulosky/atelier-store/pull/64)

## PR description

The repo's Markdown rules (`.github/instructions/markdown.instructions.md`) say every document starts with one H1 and never skips a heading level. `render_post` wrote the post title as an H2, so every release-blog PR drew the same Copilot comment (most recently #63).

Generated posts now use:
- `#` for the title;
- `##` for Summary, PR description, Commits and Files changed;
- `###` for the file areas.

`section()` reads a post's Summary and PR description back for the blog cards. It reads `##` sections in posts that start with an H1 title, and `###` in older posts, which start with an `##` title. Only the post's own level is read, so a heading from inside a PR description never passes for a section. All 19 existing posts read exactly as they did on `main` (checked by running both versions over `docs/blogs/`). Existing posts aren't rewritten.

The PR description and AI summary go through `nest_headings()` before they are inserted:
- ATX headings (`# Context`, `#### Details`) are re-levelled to start at `###`.
- Setext headings (text over a `===` or `---` line) are converted first. A bare `---` stays a thematic break.
- No heading sits more than one level below the one before it.
- Fenced code is left alone, and a fence line with an info string doesn't close an open fence.

### Tests

- A new test checks that a rendered post has exactly one H1 and never skips a level. It failed before the change.
- A new parametrised test checks that `section()` reads both the old and new heading levels.
- Existing expectations for generated posts move up one level. The excerpt tests still feed in old-format posts, and still pass.
- New tests cover `nest_headings` (Copilot's `# Context` and `#### Details` examples, setext headings and their paragraph rules, fences) and `section()` ignoring a `## Summary` from inside a PR description, whether nested or in a fenced example. Each fails on the code before its fix.
- 94 of 94 pass. `nest_headings` also matches markdown-it-py (CommonMark) headings on 160,000 random inputs.
