# fix(release): Scan Markdown blocks in one pass with a container stack

- **Release tag:** `v0.0.32`
- **Source PR:** [#77](https://github.com/mpaulosky/atelier-store/pull/77)

## PR description

Closes #75

### What

Follow-up to #71, fixing the review threads left open when it merged:

1. **No more `RecursionError`.** `scan_blocks()` recursed once per nested quote or list item, so `"> " * 1100 + "# Context"` crashed `nest_headings()` and would abort the release workflow.
2. **Linear time.** Deciding whether a line was lazy continuation re-scanned the whole block so far. That made long quoted or list paragraphs quadratic (8,000 lazy lines took about 9 s) and deep nesting with lazy lines exponential (a 30-deep quote with 200 lazy lines didn't finish within 120 s).
3. **Test helper scope.** `heading_levels()` kept fence and comment state global. A fence opened by `> ` + three backticks stayed open after the quote ended, so a later top-level `# Heading` went uncounted.

### How

`scan_blocks()` now follows CommonMark's block algorithm in one pass with an explicit container stack:

- Each line matches the open quotes and list items, outermost first.
- If not all match, the line lazily continues the open paragraph unless it opens a new block. Here any list item opens one.
- Otherwise, the unmatched containers close and new quotes and list items open before the line's content is read.

There's no recursion and there are no dry runs, and `starts_block()` gives way to `interrupts_paragraph()`, which also drives the scan. The file is net smaller (+143/−176).

`heading_levels()` remembers the quote depth and list indent where a fence or comment opened, and closes it when a line falls outside that container.

### A review finding I didn't adopt

A "previously missed" note on #71 said `> paragraph` followed by `2. # Context` should be lazy quote text. The reference implementation (`commonmark.py`) renders it as a new ordered list containing an H1. In CommonMark, the rule that only a non-empty item numbered 1 can interrupt a paragraph applies only when every container matched and the paragraph is the innermost block. When the quote doesn't match, any list item opens a new block. This PR follows the reference, and tests pin it.
